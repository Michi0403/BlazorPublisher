PublisherStudio v1.0.64 source changes
========================================

Scope
-----
This release removes the duplicate hotkey-event contract left by the v1.0.63 streaming reorganization and strengthens the repository architecture so same-named in-process contract copies and global-using collisions are rejected automatically.

No streaming route, provider behavior, publication format, Picture Studio format or export contract changed.

Compile-error repair
--------------------
Changed:
- src/PublisherStudio.Web/Services/Streaming/MediaHost/StreamingMediaHostClient.cs

Removed:
- PublisherStudio.Services.Streaming.MediaHost.MediaHostHotkeyEvent
- identical property-by-property mapping from the Domain event into the Service-local event

Kept as the only authoritative declaration:
- src/PublisherStudio.Web/Domain/Streaming/StreamingRuntimeContracts.cs
- PublisherStudio.Domain.Streaming.MediaHostHotkeyEvent

StreamingMediaHostClient.ReadEventsAsync now returns IReadOnlyList<MediaHostHotkeyEvent> directly from StreamingSessionUseCases. GlobalHotkeyService, MediaSessionRegistry, StreamingSessionUseCases, StreamingSessionService and Editor therefore resolve one type identity instead of two ambiguous simple names.

Architecture contract revision
------------------------------
Updated:
- AGENTS.md
- docs/ARCHITECTURE.md
- docs/STREAMING.md
- docs/architecture/system-overview.md
- docs/architecture/streaming.md
- VALIDATION.md
- README.md
- RELEASE.md

Added:
- docs/decisions/ADR-006-canonical-shared-contract-ownership.md

The enforced rule is now:
- one semantic request/event/state/result has one authoritative declaration;
- cross-root shared contracts belong to the established Domain or Models owner;
- Services and in-process facades reuse that type directly;
- Services may not shadow Domain/Models types with the same simple name;
- provider/protocol/process/serialization DTOs require a real boundary, an explicit boundary name and one mapping point;
- a contract move removes the former declaration in the same change;
- GlobalUsings*.cs is treated as one project-wide symbol scope and must remain collision-free.

Automated prevention
--------------------
Added:
- tests/csharpContractOwnership.test.mjs

Updated:
- tests/architectureContract.test.mjs
- tests/fontIntegration.test.mjs
- tests/streamingRuntime.test.mjs
- src/PublisherStudio.Web/package.json

The new suite scans public/internal C# declarations and rejects:
- Domain/Models-to-Services shadow types;
- duplicate simple names visible through globally imported namespaces;
- more than one MediaHostHotkeyEvent declaration;
- reintroduction of a Service-local event mapping in StreamingMediaHostClient.

Compatibility
-------------
Preserved:
- /api/mediahost, /stream and /watch route families
- Chat, ingest and WebRTC connection entry roles
- native capture, Windows process loopback and FFmpeg orchestration
- Twitch OAuth and provider output configuration
- separate stop-streaming, stop-recording and stop-session controls
- HLS/RTSP/LAN playback and hotkey behavior
- protected local streaming settings
- publication format 1.47
- Picture Studio format 1.2

Upgrade cleanup
---------------
The source archive contains no bin/obj output. When these files are copied over a built v1.0.63 checkout, clean those folders before compiling so Visual Studio cannot retain the removed duplicate event type in a design-time assembly.

Git history
-----------
The supplied v1.0.63 source archive contains no .git directory. Commit-level history was unavailable; the v1.0.63 source and release documents were used as the baseline.
